= Jinfer (Qxotic) Models
:extensions: io.quarkiverse.langchain4j:quarkus-langchain4j-jinfer

include::./includes/attributes.adoc[]
include::./includes/customization.adoc[]

https://qxotic.ai/[Qxotic] provides *jinfer*, an engine that runs Large Language Models (LLMs) *locally and purely in Java*, embedded in your Quarkus application.
This extension integrates jinfer's LangChain4j support, exposing chat, streaming chat, embedding, scoring (rerank), decision, audio transcription, and text-to-speech models backed by in-process GGUF inference.

== Quick start

Add the extension and choose a model:

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>io.quarkiverse.langchain4j</groupId>
    <artifactId>quarkus-langchain4j-jinfer</artifactId>
    <version>{project-version}</version>
</dependency>
----

[source,properties]
----
quarkus.langchain4j.jinfer.chat-model.model=LiquidAI/LFM2.5-1.2B-Instruct-GGUF:Q8_0
----

Then define an AI service and start `quarkus dev`. The model is downloaded on first use:

[source,java]
----
@RegisterAiService
public interface Assistant {
    String chat(String message);
}
----

[#_prerequisites]
== Prerequisites

=== Java 25

This extension requires *Java 25 or later*.

[#_vector_api]
=== Vector API

jinfer uses the https://openjdk.org/jeps/508[Java Vector API], an incubator module that must be enabled when the JVM starts.
*Dev mode and continuous testing* enable it for you. Everywhere else, add the flag once:

[cols="1,3"]
|===
|Where |How

|Production jar
|`java --add-modules jdk.incubator.vector -jar quarkus-run.jar`

|`@QuarkusTest`
|`<argLine>--add-modules jdk.incubator.vector</argLine>` in `maven-surefire-plugin`

|`@QuarkusIntegrationTest`
|`quarkus.test.arg-line=--add-modules=jdk.incubator.vector`

|Jib container image
|`quarkus.jib.jvm-additional-arguments=--add-modules=jdk.incubator.vector`

|Your own Dockerfile
|Add it to `JAVA_OPTS_APPEND`, keeping the options already there

|AOT cache
|`quarkus.package.jar.aot.additional-recording-args=--add-modules=jdk.incubator.vector`
|===

Native executables need no flag.
When a model is enabled and the flag is missing, the application fails at startup and names it.

== Configuration

Set `model` to a HuggingFace/ModelScope GGUF reference (for example `owner/repo:Q8_0`) or a path to a local GGUF file, which is never downloaded.
Start a relative path with `./`, so it is never read as a reference; it resolves against the working directory:

[source,properties]
----
quarkus.langchain4j.jinfer.chat-model.model=LiquidAI/LFM2.5-1.2B-Instruct-GGUF:Q8_0
quarkus.langchain4j.jinfer.embedding-model.model=./models/embeddinggemma-2-Q8_0.gguf
----

Models, often several GB, are downloaded by jinfer into its own resumable, sha256-verified cache on first use. Set the `JINFER_OFFLINE=1` environment variable to forbid network access.
An injected model with no `model` fails at startup with a configuration line you can paste, as does a missing Vector API flag.
A missing model, gated repository or offline miss fails when the model loads, with a `ModelNotFoundException` naming the reference.

The native CPU kernels are unpacked once into the user cache directory (`$XDG_CACHE_HOME`, or `~/.cache` on Linux) and reused by every later run.
In a container with a read-only or missing home directory, point `XDG_CACHE_HOME` at a writable volume; otherwise jinfer prints a warning and falls back to the slower pure-Java kernels.

Set `quarkus.langchain4j.jinfer.enable-integration=false` to disable the models: they then throw when used, which is useful for tests.
It applies to one configuration: a named model takes `quarkus.langchain4j.jinfer."name".enable-integration`.

=== Load at startup

Models load on first use by default. To download and load them before the application serves requests, and to stop startup if a model cannot be loaded:

[source,properties]
----
quarkus.langchain4j.jinfer.load-at-startup=true
----

A named model sets `quarkus.langchain4j.jinfer."name".load-at-startup`.
On a machine or container without the model in its cache, startup then includes the download, so give startup and liveness probes enough time.

=== Timeout

Chat requests have no deadline by default, because local generation time depends on the hardware.
Set one to stop runaway replies. The global `quarkus.langchain4j.timeout` does not apply, so a limit meant for a remote provider cannot cut local generation:

[source,properties]
----
quarkus.langchain4j.jinfer.timeout=2m
----

=== Shorter embeddings

Models trained with Matryoshka representation learning, such as https://huggingface.co/google/embeddinggemma-2[EmbeddingGemma 2], can embed at a smaller width with little loss in quality.
Set `dimensions` to store shorter vectors:

[source,properties]
----
quarkus.langchain4j.jinfer.embedding-model.model=unsloth/embeddinggemma-2-GGUF:Q8_0
quarkus.langchain4j.jinfer.embedding-model.dimensions=256
----

=== Companion files

Vision and audio input need the model's projector (`mmproj`), and Kokoro needs a voice.
Set them with `companions`, as a GGUF reference or a local path:

[source,properties]
----
quarkus.langchain4j.jinfer.chat-model.model=LiquidAI/LFM2.5-VL-450M-GGUF:Q8_0
quarkus.langchain4j.jinfer.chat-model.companions.media=LiquidAI/LFM2.5-VL-450M-GGUF/mmproj-LFM2.5-VL-450m-Q8_0.gguf
quarkus.langchain4j.jinfer.tts-model.model=simonfxr/kokoro.cpp-GGUF:Q8_0
quarkus.langchain4j.jinfer.tts-model.companions.voice=simonfxr/kokoro.cpp-GGUF/voices/kokoro-voice-af_heart.gguf
----

=== Token counting

A `TokenCountEstimator` bean counts tokens with the chat model's tokenizer, so `quarkus.langchain4j.chat-memory.type=token-window` works without extra wiring.

=== Observability

`ChatModelListener`, `EmbeddingModelListener`, `ScoringModelListener` and `DecisionModelListener` beans are notified of every call to their model type.

[#_decision_models]
=== Decision models

jinfer provides a `DecisionModel` for xref:decision-services.adoc[Decision Services], which is experimental in LangChain4j.
It runs LFM3-based Liquid d1 checkpoints, such as https://huggingface.co/LiquidAI/d1-2B-GGUF[d1-2B], and Qwen 3.5-based d3 checkpoints.
Language models and LFM2-based d1 checkpoints, such as `d1-3B`, are rejected when the model is created.

[source,properties]
----
quarkus.langchain4j.jinfer.decision-model.model=LiquidAI/d1-2B-GGUF:Q8_0
----

The model name is the GGUF file name, for example `d1-2B-Q8_0.gguf`: use it as the `threshold-by-model` key.
A decision model answers one request at a time.
